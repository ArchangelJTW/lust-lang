# ACL computation benchmark

Run `python3 benchmarks/acl/oracle.py`. The command writes `results/acl/dataset.json` and `results/acl/oracle.bin` (LSB-first, user-major, visit-minor). IDs are integer surrogates: no string, profile-array, object-access or serialization costs are measured by this reference generator.

The reference follows the JavaScript expression in section 2.2 of the input document: admin requires matching tenants; doctor requires owner or a present matching team and a non-archived visit. A doctor is **not** restricted by tenant in that expression; owner access remains possible without a team. This conflicts with the document's cross-tenant and unconditional missing-team-denial statements. These are policy ambiguities, not evidence of production behavior. The corpus uses 0x5EED42 (section 4); other sections instead specify 0xDEADBEEF. Counts are exact, but other distributions are seeded pseudo-random and approximate. No currentProfile-only or malformed/null-field test cases are included in the corpus.

The generator is not a benchmark runner and its matrix is not independent proof of production semantics.

## Computation benchmark

Run `benchmarks/acl/run.sh` from any directory. It compiles release binaries and runs three separate processes for each environment. For each input mode, each process checks all 500,000 matrix decisions plus seven explicit branch cases before measurement; on a mismatch that environment produces no timing samples and the summary fails. Each process then performs three rounds of two warmup batches and 20 timed batches. A batch checks 10,000 visits for the third ordinary doctor. Raw batch times in nanoseconds are retained in the nine process JSON files; `summary.json` contains median and p95 of batch-average ns/check, not individual request latency percentiles. Throughput is the reciprocal of median batch-average time. Sequential execution is not CPU-pinned; no confidence intervals, individual latency distribution, GC, memory, compilation or production application path are measured.

Both modes use five pre-normalized integer values: role, packed tenant pair, packed owner pair, packed team pair, and archive status. Rule evaluation includes unpacking/comparing those pairs. It excludes parsing policy text, extracting fields, profile lookup, object allocation and normalization. Values are fixed per sample but vary among visits. Runtime results include host-to-runtime calls and argument conversion; Rust is an inlined native baseline. They are not measurements of original JS objects, GrainJS, OCL, acl-core or real deployment. Seven explicit cases cover missing team/owner/admin/archive paths in addition to the generated corpus; missing values other than team and `currentProfile` are not represented.

Rules are maintained separately in `rules/policy.rs`, `policy.lust`, `policy.lua` and `policy.rhai`. The `parameters` mode passes five values to the rule. The `object` mode constructs one object per decision inside the timed loop and passes it to a separate object-reading rule: a Rust struct, Lust struct instance, Lua table or Rhai map. Consequently object timings include object construction and host-to-runtime conversion, and are not pure object field-access costs. The native Rust struct may be optimized away. They model newly materialized objects, not preexisting reused objects.

Current results are in `results/acl/v2/`. If the fork cannot build, the runner records `build_failed` and skips it without running the previously built binary; inspect `fork-build.log`. Earlier files in `results/acl/` belong to the prior parameter-only run.

Separate binaries isolate LuaJIT symbols from Lust's Lua-compatible symbols. Lust VM and enabled JIT are tested for both original and local fork; LuaJIT is tested with JIT enabled and `jit.off(); jit.flush()`; Rhai uses default engine settings. JIT enabled is not proof of native execution: inspect `jit_entries` and `jit_traces` in each report. The local fork is independently versioned and may have uncommitted changes. The corpus matrix is an executable reference interpretation, not proof of the production security policy or of fail-closed behavior for arbitrary inputs.
